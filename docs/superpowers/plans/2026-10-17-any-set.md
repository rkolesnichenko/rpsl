# A set reaching AS-ANY in an AS-path regexp — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An AS-path regexp naming an as-set that reaches AS-ANY evaluates as "any AS" in `NormalizeFilter` (so peval, consist and routecheck decide it), while every other position and API keeps today's `*AnySetError`, rtconfig refuses it, and consist warns about it.

**Architecture:** `resolve.ASNSet` gains an `any` flag. A path-only discovery mode in `resolve` builds such a set for `normalizer.path`, through a cache separate from the evaluator's AS cache, so filter position and the enumerating APIs never see one. Consumers that enumerate (`rtconfig`) refuse it; `consist` adds a Warning rule.

**Tech Stack:** Go 1.23 (module floor), rpsl's `resolve` module; tests with `go test`, models, fuzz, IRRToolSet differential when installed.

**Spec:** `docs/superpowers/specs/2026-10-17-any-set-design.md`

## Global Constraints

- go.mod floors stay at go 1.23; no new dependencies.
- API conventions C1–C3 (CLAUDE.md); `api/*.txt` is regenerated with `RPSL_API_UPDATE=1 go run ./internal/apisurface -check` and the diff reviewed; `go run ./internal/apisurface -check` passes at every commit.
- Engine purity: `resolve`, `peval`, `rtconfig`, `consist`, `irrdq`, `rpki` import no `net`.
- Never panic on any input; never guess: what cannot be decided stays an error or Undecided.
- `ExpandAS`, `ExpandPrefixes`, `ExpandPrefixRanges`, `EvalFilter`, filter position of `NormalizeFilter`, irrdq and rpslq answers and error texts are byte-identical to v0.29.0 for every input.
- `Expander.Concurrency` never changes a result; `Checker.Memo`/`FilterMemo` stay result-neutral.
- Heavy runs (check.sh with FUZZTIME, real-data tests) one at a time, alone, under the memory guard (`.superpowers/sdd/tools/memguard.sh 8 …`) with `GOMAXPROCS=4`; every figure in docs or the CHANGELOG comes from a logged run.
- All work on branch `any-set` from `main`; push, PR, merge and the v0.30.0 release wait for the user's go-ahead.

## Review Focus

1. A regexp and a negated literal naming the same set in one filter (`<AS-R$> OR NOT AS-R`, both orders): the any-set must not reach the literal; the answer is `*AnySetError`, never ANY. (Task 1, `TestNormalizeAnySetCacheIsolation`)
2. rtconfig on a deny-side any-set (`ANY AND NOT <AS-R>`): refused with `CauseAnySet`, never a written `_0`/`0` list that would permit everything. (Task 2, `TestTranslateAnySet`)
3. A graph that reaches AS-ANY at a shallow level and exceeds MaxDepth or MaxVisited deeper: `*SetTooLargeError`, as today. (Task 1, `TestAnySetLimits`)
4. A shared FilterMemo used by `NormalizeFilter` then `ExpandAS` on the same set, and the reverse: ExpandAS still `*AnySetError`, NormalizeFilter still any. (Task 1, `TestFilterMemoAnySetBothOrders`)
5. Readers that enumerate a set inside `[^…]` or `~*` (routemodel, the filter model's goRE): an any-set matches every AS / no AS as the regexp says, never "empty". (Task 3, model draws)
