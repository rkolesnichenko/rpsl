# One test for "this name is AS-ANY" — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new exported method, `types.SetName.IsAny()`, becomes the one test of whether a name
is AS-ANY or one of its four kin. All seven hand-written copies switch to it, and check.sh
refuses an eighth.

**Architecture:**
- **The method.** It goes in `types/setname.go`, beside `IsZero`.
- **The callers.**
  - `isAnySet` (resolve) and `anySets` (consist) are deleted, and their callers use the method.
  - The five `strings.EqualFold(…, "AS-ANY")` sites in policy, peval, rtconfig, consist and
    routemodel use it too.
- **The guard.** A new `scripts/check.sh` step greps non-test Go files for quoted any-names.
- **Behaviour.** No answer changes. The existing suites are the evidence, and a mutation run
  shows which existing test covers each site.

**Tech Stack:** Go 1.23, multi-module, wired by go.work. Run root-module tests (`policy`) from
the repo root, `types` tests from `types/`, and `resolve` tests from `resolve/`.

**Spec:** `docs/superpowers/specs/2026-10-27-any-name-design.md`. Read it first. Its "The
change" and "Tests" sections are the requirements.

## Global Constraints

- `IsAny` is true for exactly `AS-ANY`, `RS-ANY`, `RTRS-ANY`, `PRNG-ANY` and `FLTR-ANY`, in
  canonical form, and for nothing else.
- `types` stays a leaf. `cd types && go list -deps ./... | grep rkolesnichenko` shows only
  itself.
- The API change is one line. `RPSL_API_UPDATE=1 go run ./internal/apisurface -check` adds
  `func (SetName) IsAny() bool` to `api/types.txt`, and the diff to `api/` shows nothing else.
- No existing test file is edited outside `types`. The only exception is a test a site turns
  out to need in Task 2, Step 4.
- Heavy runs (check.sh, the mutation run, real data) go one at a time, never beside each other:
  - under `/Users/roman/DEV/rpsl/.superpowers/sdd/tools/memguard.sh 8 <timeout_s> <cmd>`;
  - with `MEMGUARD_NORMAL_PRIORITY=1`, `GOMAXPROCS=4` and `GOMEMLIMIT=6GiB` set.
- Commit messages take a lower-case package prefix, as in
  `resolve: share one MaxVisited budget across a normalization`.
- zsh: redirect a command's output to a file and print `$?` on the next line. Never read a
  status through a pipe.
- `<ws>` is this plan's workspace, the directory `sdd-workspace` prints for this plan file.
- memguard takes one command and its arguments, so a chain of commands goes through
  `sh -c '…'`.

## Review Focus

1. **A name built by template instantiation** (`AS1:AS-CUST:PeerAS`, or a template whose set
   component is `AS-ANY`, such as `AS-ANY:PeerAS`). It instantiates through `ParseSetName`
   (`policy/template.go:46`) into a hierarchical name, so `IsAny` is false, as `EqualFold` was.
   Pinned by the `AS-ANY:AS1` row of `TestSetNameIsAny` (Task 1).
2. **A scoped reference** (`RIPE::AS-ANY`). The engine reads `ref.Name()`, so it is still
   AS-ANY. That is unchanged behaviour, covered by the existing `isAnySet` call sites. Its
   reviewer check is that no call site was switched to compare a `SetRef`'s text.
3. **A name read from JSON or text.** `UnmarshalText` goes through `ParseSetName`
   (`types/text.go:59`), so `as-any` decodes to a name whose `IsAny` is true. Pinned in Task 1
   by a `TestSetNameIsAny` row that decodes `"as-any"` through `UnmarshalText`.
4. **A lost import or a dead helper.** `pathall.go` uses `strings` only for its `EqualFold`, so
   it loses the import. The other four files use `strings` elsewhere. `go vet` and the build
   (Task 2) catch both a dead import and a dead helper.
5. **A false alarm from the guard** on a comment that quotes `"AS-ANY"` in double quotes. Today
   none exists, and the step's own run on the clean tree pins that (Task 3, Step 3).

### Task 3: check.sh refuses another copy

**Files:**
- Modify: `scripts/check.sh` (a new step after "engine purity", before "api surface")

**Interfaces:**
- Consumes: the existing `gofiles` helper (check.sh:23) and `bad` and `step`.

- [ ] **Step 1: Add the step**

The spec fixes three rules:
- The listing's status is tested on its own, like the gofmt step.
- A grep that finds nothing (status 1) is the good case. Only a status above 1 is an error.
- `types/setname.go` and `resolve/internal/irrdoracle/cases.go` are the only allowed files, and
  `_test.go` files are skipped.

The body:

```sh
step "any names: only types spells AS-ANY and its kin (types.SetName.IsAny)"
# A quoted AS-ANY, RS-ANY, RTRS-ANY, PRNG-ANY or FLTR-ANY outside types is a
# copy of SetName.IsAny. grep exits 1 when nothing matches, the good case, so
# only a status above 1 fails the step.
any_files=$(mktemp) || bad "could not list Go files"
if gofiles > "$any_files"; then
	any_hits=$(xargs -0 sh -c 'grep -H -n -i -E "\"(AS|RS|RTRS|PRNG|FLTR)-ANY\"" "$@"; [ $? -le 1 ]' _ < "$any_files") ||
		bad "any names: grep failed"
	any_hits=$(printf '%s\n' "$any_hits" |
		grep -v -E '^([^:]*_test\.go|types/setname\.go|resolve/internal/irrdoracle/cases\.go):')
else
	bad "could not list Go files"
	any_hits=
fi
rm -f "$any_files"
[ -z "$any_hits" ] || bad "a copy of types.SetName.IsAny: $any_hits"
```

The second `grep -v` is read for its output only, so its status (1 when everything was
allowed) does not matter.

A dry run of this body, on main at 0c00b6e before any site changed, failed with the seven
sites in the spec's table and nothing else. `irrdoracle/cases.go` and the test files were left
out, as intended.
